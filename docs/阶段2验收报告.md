### 3.2 实现的关键设计点

| 设计点 | 实现方式 |
|---|---|
| **原子落盘** | 处理器只写 `<guid>.tmp<ext>`；成功后 `File.Move` 到最终路径。同卷移动是原子的 |
| **临时文件带正确扩展名** | 命名成 `xxx.tmp.mp4` —— ffmpeg 靠扩展名决定输出容器格式 |
| **源文件零改动** | 只读源路径，从不写入或删除。测试用「大小 + 时间戳 + 内容哈希」三重校验 |
| **崩溃恢复** | 启动时 `RecoverInterruptedAsync()` 把 `Running` 任务退回 `Queued`；`.tmp` 目录全清 |
| **烧号不复用** | 序号在计划阶段分配；失败的任务序号作废，比冒重号风险安全 |
| **失败重试上限** | `Attempts < 3` 退回队列，达到上限转 `Failed`，不会无限重试 |
| **NVENC 探测 + 回退** | 启动时跑一次真实编码验证；失败自动用 `libx265` |
| **磁盘空间预检** | 按 `视频×0.5 + 照片×4 + 音频×1` 估算，留 1.2 倍余量 |
| **进度节流** | 界面回调每次发（内存操作），落库每 5% 一次（避免打满磁盘） |
| **`INSERT ... RETURNING Id`** | 导入必须拿到真实主键；`OR IGNORE + last_insert_rowid()` 在冲突时会错配 |

### 3.3 生成的命令（实测生效）

```bash
# 视频：H.265 + NVENC
ffmpeg -hide_banner -y -nostdin -i "<源>"
  -map 0:v:0 -map 0:a?
  -c:v hevc_nvenc -preset p5 -tune hq -rc vbr -cq 24 -b:v 0
  -profile:v main -pix_fmt yuv420p
  -tag:v hvc1                    # 缺了它部分剪辑软件播不了 HEVC-MP4
  -c:a copy                      # 源音频已兼容 → 直接复制
  -movflags +faststart
  -progress pipe:1 -nostats
  "<库根>\.tmp\<guid>.tmp.mp4"

# 照片：→ PNG
ffmpeg -hide_banner -y -nostdin -i "<源>"
  -map 0:v:0                     # HEIC 是多图容器，必须显式取主图
  -frames:v 1 -pix_fmt rgb24
  -pred mixed -compression_level 6
  -update 1 "<库根>\.tmp\<guid>.tmp.png"
```

### 崩溃恢复的实测细节

测试方式：导入 78 项后启动处理，**1.2 秒时用 `CancellationToken` 强行中断**（模拟强杀），然后**重建一整套服务对象**（相当于重开程序）：

```
中断时状态: 就绪 25 / 排队 47 / 运行中 6 / 失败 0
                    ↑ 6 个任务卡在 Running（进程被杀时的状态）
重启后:     排队 0 / 运行中 0 / 完成 78 / 失败 0
            本轮处理 53 项，耗时 4.3s
```

`RecoverInterruptedAsync()` 把这 6 个 `Running` 任务退回队列，续跑时重新处理，最终 78 项全部完成且产物完整。

## 6. 过程中发现并修复的问题

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | 冒烟测试方法名以数字开头（`10bit源判定为HDR`） | 编译失败 | 改名为 `十倍位深的源判定为HDR` |
| 2 | 命名测试插入的假记录未清理 | 缩略图补全对它重试 3 次并计入失败，污染测试结果 | 测试结束前 `DeleteAsync` |
| 3 | `CleanOrphanTempFiles` 只删 `*.tmp` | 新的临时文件名是 `xxx.tmp.mp4`，**崩溃残留永远清不掉** | 改为清空整个 `.tmp` 目录 |

> 第 3 个是真 bug：阶段 1 写的清理逻辑按 `*.tmp` 过滤，
> 而阶段 2 的临时文件必须带目标扩展名（`xxx.tmp.mp4`），两者不匹配。
> 后果是每次崩溃都会在库里留下几个 GB 的垃圾文件且永不清理。
